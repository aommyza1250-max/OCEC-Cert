# เช็คลิสต์ก่อนเปิดให้ผู้ปกครองใช้จริง

ไล่ติ๊กทีละข้อ **ห้ามข้าม** โดยเฉพาะหมวดความปลอดภัย
เพราะเกียรติบัตรเป็นข้อมูลส่วนบุคคลของเด็ก และบางอย่างแก้ย้อนหลังไม่ได้

---

## 1. ความปลอดภัย

- [ ] **เปลี่ยน `ADMIN_PASSWORD` จากค่า dev แล้ว**
      ค่า dev คือ `dev-admin-1234` ถ้ายังเป็นค่านี้อยู่บน production ถือว่าไม่มีรหัสผ่านเลย
- [ ] **`SESSION_SECRET` สุ่มใหม่สำหรับ production** (`openssl rand -hex 32`)
      ไม่ใช่ค่าเดียวกับในเครื่อง dev
- [ ] **`WORKER_SHARED_SECRET` สุ่มใหม่** และตรงกันทั้ง web กับ worker
- [ ] **service `worker` ไม่มีโดเมนสาธารณะ** (Railway → worker → Settings → Networking ต้องว่าง)
- [ ] **ไฟล์ PDF และ ZIP ต้นฉบับเข้าไม่ได้จากภายนอก**
      ```bash
      curl -s -o /dev/null -w "certificates: %{http_code}\n" https://files.example.com/certificates/x.pdf
      curl -s -o /dev/null -w "sources:      %{http_code}\n" https://files.example.com/sources/x.zip
      # ทั้งคู่ต้องได้ 403 — ถ้าได้ 200 หรือ 404 ให้กลับไปตรวจ WAF rule
      # ใน docs/setup-cloudflare-r2.md ข้อ 4 ทันที
      ```
- [ ] **รูป preview เข้าได้** (ต้องได้ 200)
      ```bash
      curl -s -o /dev/null -w "previews: %{http_code}\n" https://files.example.com/previews/<ไฟล์จริง>.webp
      ```
- [ ] ไม่มีไฟล์ `.env` หรือไฟล์เกียรติบัตรจริงหลุดเข้า git
      ```bash
      git status --short --untracked-files=all | grep -E "\.env$|\.pdf$|\.xlsx$" || echo "สะอาด"
      ```

## 2. ความถูกต้องของข้อมูล

- [ ] **นำเข้าจริง 1 รอบแล้วตรวจยอดก่อน publish**
      ในหน้าแอดมิน ดูสรุปผลว่า:
      - `หน้าทั้งหมด` ตรงกับจำนวนหน้าใน ZIP จริง
      - `อ่านชื่อไม่ออก` = 0
      - `รางวัลบนหน้าไม่ตรงโฟลเดอร์` = 0
      - `ยังไม่มีคู่` = 0 และ `ชื่อซ้ำ รอตัดสิน` = 0
- [ ] **ตรวจ `รางวัลไม่ตรงกับ Excel` ว่าอธิบายได้**
      ตัวเลขนี้ไม่ใช่ข้อผิดพลาดเสมอไป — ของจริงผู้ที่ได้ `PERFECT SCORER`
      จะมีใบ Gold ด้วย ทำให้ไม่ตรงกับ Excel อย่างถูกต้อง
      แต่ถ้าตัวเลขสูงผิดปกติ ให้ตรวจว่าจัดไฟล์เข้าโฟลเดอร์ถูกไหม
- [ ] **สุ่มเปิด preview 3–5 ใบเทียบกับไฟล์ต้นฉบับ** ว่าชื่อและรางวัลตรงกัน
- [ ] **ตรวจคนที่ได้หลายใบ** ว่าได้ครบทุกใบจริง
      ```sql
      SELECT s.name_en, string_agg(c.award, ', ') FROM certificates c
      JOIN students s ON s.id = c.student_id GROUP BY s.id, s.name_en HAVING COUNT(*) > 1;
      ```
- [ ] **กด publish แล้วค้นชื่อจริงดู** ว่าเจอและโหลดได้

## 3. ประสบการณ์ผู้ใช้

- [ ] เปิดหน้าค้นหาบน **มือถือจริง** แล้วลอง:
      - ค้นชื่อภาษาอังกฤษพิมพ์เล็ก
      - กดดูรูป preview ขยาย
      - กดดาวน์โหลด แล้วเปิดไฟล์ที่โหลดมาได้จริง
- [ ] ชื่อไฟล์ที่โหลดได้อยู่ในรูป `{FNAME}_{LNAME}_{รายการสอบ}_{รอบ}_{รางวัล}_{ปี}.pdf`
- [ ] ค้นชื่อที่ไม่มีในระบบ แล้วข้อความที่ขึ้นอ่านแล้วเข้าใจว่าต้องทำอะไรต่อ

---

## 4. รับโหลดได้จริง

- [ ] รันทดสอบโหลดจำลองผู้ใช้ 600 คนพร้อมกัน
      ```bash
      BASE_URL=https://cert.example.com k6 run scripts/loadtest.js
      ```
      **เกณฑ์ผ่าน:** `http_req_duration p(95) < 500ms` และ `http_req_failed < 1%`
- [ ] ถ้าไม่ผ่าน ตรวจว่า index ค้นหายังอยู่ครบ
      ```sql
      SELECT indexname FROM pg_indexes WHERE tablename = 'students';
      -- ต้องมี students_name_th_normalized_trgm_idx และ students_name_en_normalized_trgm_idx
      ```

## 5. สำรองข้อมูลและการกู้คืน

- [ ] **สำรองฐานข้อมูล** — ทดลอง export จริงหนึ่งครั้งให้แน่ใจว่าทำได้
      ```bash
      # ดึง DATABASE_URL จาก Railway → Postgres → Variables → Connect → Postgres Connection URL
      pg_dump "<DATABASE_URL>" -Fc -f ocec-$(date +%Y%m%d).dump
      ```
      เก็บไฟล์ไว้นอก Railway และตั้งเตือนให้ทำซ้ำหลังนำเข้าทุกรอบ
- [ ] **เข้าใจว่าไฟล์ต้นฉบับใน `sources/` เก็บไว้ทำไม**
      ZIP และ Excel ต้นฉบับคือสิ่งที่ใช้สร้างทุกอย่างใหม่ได้ ถ้าฐานข้อมูลเสีย
      ยังนำเข้าใหม่จากไฟล์เหล่านี้ได้ทั้งหมด — **อย่าลบจนกว่าจะมั่นใจว่าสำรองฐานข้อมูลไว้แล้ว**
- [ ] **รู้ว่าถ้าเผยแพร่ผิดต้องทำอะไรก่อน**
      → กด "ยกเลิกการเผยแพร่" ในหน้าแอดมินทันที แล้วค่อยแก้
      รายละเอียดอยู่ใน [runbook.md](runbook.md) หัวข้อ "จับคู่ผิดคน"

---

## 6. ส่งมอบ

- [ ] แอดมินที่จะใช้งานจริงได้ลองนำเข้าเองแล้ว 1 รอบ โดยมีคนคอยช่วย
- [ ] แอดมินรู้ว่า [runbook.md](runbook.md) อยู่ที่ไหน และเปิดอ่านได้เมื่อมีปัญหา
- [ ] แอดมินรู้ว่าต้องจัดโฟลเดอร์ใน ZIP ยังไง (gold / silver / bronze / merit / perfect score)
- [ ] มีคนรู้รหัสผ่านแอดมินอย่างน้อย 2 คน และเก็บไว้ใน password manager ไม่ใช่ในแชท
