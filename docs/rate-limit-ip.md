# การจำกัดจำนวนครั้งต่อ IP — อ่าน IP ของผู้ใช้จากไหน

## ทำไมต้องมีเอกสารนี้

การจำกัดจำนวนครั้งมีไว้กันคนไล่ยิงเพื่อดูดรายชื่อผู้เข้าสอบ (เรื่อง PDPA ไม่ใช่เรื่องโหลดเซิร์ฟเวอร์)
และกันการเดารหัสผ่านหน้าแอดมิน ทั้งหมดขึ้นกับการตอบคำถามเดียว: **IP จริงของผู้ใช้อยู่ใน header ตัวไหน**

ตอบผิด = ระบบยังตอบ 200 ทุกครั้งเหมือนทำงานปกติ **ไม่มี error ไม่มี log อะไรฟ้องเลย**
กว่าจะรู้ก็ต่อเมื่อมีคนดูดรายชื่อออกไปแล้ว ที่นี่เคยตอบผิดมาแล้วสองรอบ

| รอบ | อ่านจาก | ผลตอนทดสอบกับ production |
|---|---|---|
| 1 | `x-forwarded-for` ตัวซ้ายสุด | ยิง 35 ครั้งด้วยเลขปลอมคนละค่า ผ่านหมด (ลิมิตตอนนั้น 30/นาที) |
| 2 | `x-forwarded-for` ตัวขวาสุด | ยิง 340 ครั้ง ผ่านหมด ทั้งแบบปลอมและไม่ปลอม |
| 3 | `x-real-ip` | ใช้อยู่ตอนนี้ — ทดสอบแล้วปลอมไม่ได้ ทั้ง login และหน้าค้นหากันได้ตรงตามลิมิต |

มีกับดักซ้อนอีกชั้นตอนตรวจผลรอบที่ 3: หน้าค้นหาตอบ 200 เสมอแม้ถูกจำกัด
ทำให้เข้าใจผิดว่าตัวแปรลิมิตถูกตั้งไว้ให้ปิด ทั้งที่ทำงานปกติ วิธีวัดที่ถูกอยู่ในข้อ 2

รอบที่ 2 ผิดเพราะ **เดา** ว่า proxy จะต่อท้าย IP จริงลงใน `x-forwarded-for` เอง
ซึ่งเป็นพฤติกรรมมาตรฐานของ reverse proxy หลายเจ้า แต่ไม่ใช่ของ Railway

## ของจริงบน Railway (ตรวจเมื่อ 18 ก.ย. 2569)

```
x-forwarded-for: 27.130.180.201, 152.233.68.97
                 └ IP ผู้ใช้จริง ┘  └ proxy ภายในของ Railway ┘
x-real-ip:       27.130.180.201
x-railway-edge:  sin1
```

- **`x-real-ip` คือ IP จริงของผู้ใช้** Railway เป็นคนใส่ให้จากผู้ที่เชื่อมต่อเข้ามา
- `x-forwarded-for` ตัวซ้ายสุดก็เป็น IP จริง **แต่ผู้ใช้ส่ง header นี้มาเองได้** จึงไม่ใช้
- ตัวขวาสุดเป็น IP ของ proxy ภายใน ไม่ผูกกับตัวผู้ใช้ และเปลี่ยนไปตาม proxy ที่รับงาน

## วิธีตรวจเมื่อย้ายผู้ให้บริการ หรือเพิ่ม CDN/proxy คั่นหน้าเว็บ

**ต้องตรวจใหม่ทุกครั้ง** อย่าเดาจากพฤติกรรมของเจ้าเดิม

### 1. ดูว่า header มาถึงแอปหน้าตาเป็นยังไง

เข้าสู่ระบบแอดมิน แล้วเปิด `https://<โดเมน>/api/admin/client-ip` ในแท็บเดิม
จะได้ JSON ที่บอกว่า header เกี่ยวกับ IP มีอะไรบ้างและค่าเป็นอะไร

กด refresh ซ้ำหลายครั้งแล้วดู `processId` ด้วย:
**ถ้าเลขเปลี่ยนไปมา แปลว่ารันหลาย instance** ตัวนับที่เก็บใน memory จะถูกหารตามจำนวน instance
(ลิมิต 300 กับ 3 instance = กันได้จริงที่ 900) ถ้าเป็นแบบนั้นต้องย้ายตัวนับไปเก็บที่ Postgres

### 2. ทดสอบว่าปลอมไม่ได้จริง

> ⚠️ **หน้าค้นหาไม่ตอบ 429** เพราะเป็นหน้าเว็บสำหรับคนอ่าน ไม่ใช่ API
> พอโดนจำกัดมันตอบ **200 พร้อมข้อความ "ค้นหาถี่เกินไป"** (หน้าเว็บของ Next.js
> ตั้งรหัสสถานะเองไม่ได้) ถ้าวัดด้วยการนับรหัสสถานะจะเห็น 200 ครบทุกครั้ง
> แล้วสรุปผิดว่าการจำกัดไม่ทำงาน — **เคยสรุปผิดแบบนี้มาแล้ว** ให้วัดจากเนื้อหาหน้าแทน

ใช้หน้า login เป็นตัววัด เพราะเป็น API จริงที่ตอบ 429 ตรง ๆ และลิมิตต่ำ (10/นาที)
เห็นผลเร็วและไม่ต้องยิงเยอะ

```bash
# ปลอม x-forwarded-for คนละค่าทุกครั้ง — ต้องมี 429 โผล่มาที่ครั้งที่ 11
for i in $(seq 1 15); do
  curl -s -o /dev/null -w "%{http_code} " \
    -H "x-forwarded-for: 198.51.100.$i" \
    -X POST -H "content-type: application/json" -d '{"password":"wrong"}' \
    "https://<โดเมน>/api/admin/login"
done; echo

# ปลอม x-real-ip คนละค่าทุกครั้ง — ต้องมี 429 โผล่มาเหมือนกัน
# ถ้าไม่มี แปลว่า proxy ปล่อยให้ผู้ใช้ตั้ง x-real-ip เองได้ ต้องเปลี่ยนไปใช้ header อื่น
for i in $(seq 1 15); do
  curl -s -o /dev/null -w "%{http_code} " \
    -H "x-real-ip: 198.51.100.$i" \
    -X POST -H "content-type: application/json" -d '{"password":"wrong"}' \
    "https://<โดเมน>/api/admin/login"
done; echo
```

**ผลที่ต้องได้:** `401` สิบครั้งแล้วตามด้วย `429`
ถ้าได้ `401` ครบ 15 ครั้ง แปลว่ายังปลอมได้อยู่ **ห้ามเปิดให้ใช้งานจริง**

> ยิงถี่ ๆ ติดกันหลายรอบจะทำให้ถังยังไม่รีเซ็ต รอ 1 นาทีก่อนทดสอบรอบถัดไป

ส่วนหน้าค้นหาวัดจาก**เนื้อหาหน้า** ลิมิต 300/นาที ยิง 340 ครั้งต้องได้ประมาณ 300/40

```bash
seq 1 340 | xargs -P 20 -I{} sh -c \
  'curl -s "https://<โดเมน>/?q=TEST{}" | grep -q "ค้นหาถี่เกินไป" && echo จำกัด || echo ผ่าน' \
  | sort | uniq -c
```

ผลจริงที่วัดได้เมื่อ 18 ก.ย. 2569: `300 ผ่าน` / `40 จำกัด` ตรงตามลิมิตพอดี

### 3. แก้ที่ไหน

`apps/web/src/lib/rate-limit.ts` ฟังก์ชัน `clientIp()` — แก้แล้วต้องเพิ่มเทสใน
`rate-limit.test.ts` ด้วย โดยใช้ header ชุดจริงที่เห็นในขั้นที่ 1 เป็นตัวตั้ง

## ค่าลิมิตปัจจุบัน

| อะไร | ค่า | ตัวแปร |
|---|---|---|
| ค้นหา | 300 ครั้ง/นาที/IP | `SEARCH_RATE_LIMIT_PER_MIN` |
| เข้าสู่ระบบ | 10 ครั้ง/นาที/IP | `LOGIN_RATE_LIMIT_PER_MIN` |

ตั้งเป็น `0` เพื่อปิดชั่วคราว (เช่นตอนทดสอบโหลด) — **อย่าลืมตั้งกลับ**

⚠️ ตั้งค่าเป็นค่าว่างใน Railway มีผลเท่ากับ `0` คือปิดการจำกัด
ถ้าจะใช้ค่าปริยายให้ **ลบตัวแปรทิ้ง** ไม่ใช่เว้นค่าว่างไว้
