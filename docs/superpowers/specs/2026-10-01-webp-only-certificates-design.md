# WebP-only certificate delivery and legacy migration

Date: 2026-10-01

## Goal and scope

Administrators continue to upload PDF bundles and individual PDFs. Parsing, identity checks, award assignment, matching, publication, and manual review retain their current decisions. Recipients preview and download a single high-quality WebP per certificate. New imports keep the current split-PDF and preliminary-preview steps for matching and admin review. As soon as a page is successfully matched, the worker renders and verifies its high-quality WebP, switches the page/certificate to that image, then deletes that page's split PDF. Existing matched split PDFs are converted after deployment and removed only after the replacement WebP is verified and active. Source ZIPs and individual upload PDFs remain under the existing source-cleanup rules until the batch is safe to clear. Roster spreadsheets remain retained as before.

Two branches in this repository support the rollout. `codex/webp-certificates-migration` contains the product change and a temporary admin migration control. A second branch, based on the first, removes the temporary control and migration-only API/job after production migration is complete and verified. The second branch must not be deployed before that verification. The original checkout's unrelated local changes are outside this work.

## Asset format and delivery

Use one high-quality WebP per published certificate for both the preview/lightbox and the download. Unresolved staging pages may retain their preliminary preview until matched. Keep 180 DPI and set WebP quality to 85: a representative 2105 × 1489 WebP measured 856,098 bytes at quality 90 and 626,690 bytes after re-encoding at quality 85 (about 27% smaller); close inspection showed small text and signatures remained clear. An earlier, different one-page PDF produced a 419 KiB WebP, showing that size varies by source artwork. Monitor quality 85 with more certificates. Keep browser lazy loading, and test result pages containing several certificates. Download continues as a presigned R2 GET redirect with a `.webp` filename and `image/webp` content type; the Next.js server never transfers the image bytes. Existing certificate download URLs, including `?format=pdf`, return the WebP so bookmarks do not break. The public UI removes the PDF button and PDF wording.

Use versioned object keys for new high-quality WebPs. Never overwrite a currently referenced image during migration, because a failed write or a cached old object could produce an inconsistent result. Keep the current public `previews/` access pattern unless a separate access-control change is explicitly requested.

## New imports and individual add/replace

Read each PDF from the uploaded source on worker disk, processing one PDF at a time. Preserve the current per-page split PDF, preliminary preview, staging row, text parsing, and matching flow. Ambiguous and duplicate-name cases still require admin resolution and keep their split PDF and preview. After a page is matched and a certificate is accepted, render a new high-quality WebP from that split PDF, validate its dimensions and decodability, upload it, switch the page/certificate image reference, and delete only that split PDF and superseded preliminary preview. Publication of a new certificate requires the high-quality image to be ready. If conversion fails, keep the split PDF and preliminary preview for retry and do not publish that new certificate.

The individual add/replace path keeps its current checks for roster entry, certificate number, name, award and selected page. It follows the same split-PDF, preliminary-preview, matching, then high-quality WebP finalization sequence. Replacing a certificate updates the asset reference and preserves existing audit and expiry behavior. A failed add/replace retains its uploaded source for diagnosis, and job rollback deletes only outputs created by that job. Image-key-based uniqueness and publication snapshots replace the PDF-key-dependent logic. When migrating a previously approved supplemental-only set without changing its identity or award, preserve its approval by translating the snapshot in the same database transaction as the asset switch; a genuinely replaced file still invalidates the prior approval.

## Legacy migration

Add an admin-only, one-time control labelled “ย้ายเกียรติบัตรเก่าเป็น WebP”. It queues a worker job and shows dry-run counts, progress, bytes before/after, failures, and a retry action. The web request only enqueues work. A job lock prevents concurrent migration of the same batch and conflicting intake, replacement, source cleanup, expiration, or deletion operations.

For each legacy matched staging page/certificate with a split-PDF key, download that PDF to worker disk. Render one new versioned WebP and validate upload success, dimensions, format and retrievability. Atomically switch all database references for that page/certificate and any applicable supplemental-only approval snapshot. Only then delete the old split PDF and old image. If conversion or validation fails, leave both old assets and database references untouched, record the error, and continue to other pages. If deletion fails after the database switch, retain the old-object keys in a cleanup record so retry can remove them. Reruns skip pages already switched and retry failed or orphan-cleanup items. Do not mark migration complete until every in-scope matched legacy page is migrated and no deletion backlog remains. List unresolved pages separately; they retain their split PDFs until the normal admin matching flow resolves them, after which the same finalization runs. The current `rerender_previews.py` overwrites image keys; it is not used as the production migration mechanism.

Existing expired certificates are excluded from image recreation and remain expired. Cases where a legacy PDF is missing are reported for administrator review rather than silently skipped or marked complete. No real certificate PDF or roster is committed to Git.

## Database, cleanup, and compatibility

Make split-PDF references nullable because finalized certificates have no PDF, while unresolved staging pages may still have one. Require a high-quality WebP for publication of new certificates; legacy published certificates remain downloadable from their current image during migration. Adapt `staging_pages`, `certificates`, worker matching, publish rules, seed data, expiry cleanup, batch deletion, and source cleanup to image-first behavior. Keep schema indexes declared in Prisma. Python inserts continue to supply UUIDs in code. Existing source cleanup waits for publication, roster coverage, and no unresolved pages; additionally require every accepted certificate to have a verified high-quality WebP before deleting its source. Keep the existing two-year file-expiry policy, now deleting WebP and clearing its key. A migration must never revive an expired certificate.

## Verification and rollout

Test the shared intake flow with synthetic bundle PDFs, unmatched/ambiguous pages retaining their PDFs, matched-page image finalization and PDF deletion, foreign pages, individual add and replace, job rollback, supplemental-only approval, download redirect, and expiration. Test migration interruption after upload, after database switch, and before deletion, then rerun to prove no published certificate loses its downloadable asset. On staging, measure WebP size and load time with several representative certificates. Deploy the migration branch, run dry-run and then the admin job, inspect failure and cleanup reports, and confirm all active certificates resolve to WebP. Only afterward deploy the follow-up branch that removes the temporary migration control and code.
