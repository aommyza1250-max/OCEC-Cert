# สเปกการรับและนำเข้าข้อมูลเกียรติบัตร (Data Intake & Processing Spec)

เอกสารนี้สรุปข้อกำหนด รูปแบบโครงสร้างไฟล์ต้นฉบับ และกระบวนการนำเข้าข้อมูล (Data Intake Workflow) ก่อนนำเข้าสู่ระบบ OCEC-Cert

---

## 1. ภาพรวมรอบการสอบและรูปแบบไฟล์ต้นฉบับ (Raw Data Overview)

การสอบจัดขึ้นเป็น 2 รอบหลัก โดยมีลักษณะไฟล์เกียรติบัตรที่ได้รับมาดังนี้:

| รอบการสอบ | กลุ่มผู้สอบในไฟล์ PDF | การแบ่งไฟล์ตามรางวัล (Award) | เงื่อนไขการคัดกรองประเทศ |
|---|---|---|---|
| **1. รอบ Heat (รอบคัดเลือก)** | เฉพาะของไทย (Domestic) | รวมเล่ม PDF แยกตามโฟลเดอร์เหรียญรางวัล | ตัดแยกทุกหน้า ไม่ต้องกรองสัญชาติ |
| **2. รอบ Final (รอบชิงชนะเลิศ)** | รวมทุกประเทศ (International) | รวมเล่ม PDF แยกตามโฟลเดอร์เหรียญรางวัล | **ต้องสแกนคัดเฉพาะคนไทย** (`from THAILAND`) ข้ามชาติอื่น |

### ประเภทรางวัล/เหรียญรางวัล (Awards)
ไฟล์ PDF รวมเล่มจะถูกจัดกลุ่มมาในโฟลเดอร์ 5 รางวัล ได้แก่:
1. `gold` (เหรียญทอง)
2. `silver` (เหรียญเงิน)
3. `bronze` (เหรียญทองแดง)
4. `merit` (รางวัลชมเชย)
5. `perfect score` (คะแนนเต็ม)

---

## 2. โครงสร้างไฟล์ Excel รายชื่อ (Roster Sheet)

ไฟล์สรุปรายชื่อผู้เข้าสอบจากส่วนกลางจะมีหัวตาราง (Columns) ดังนี้:

| หัวคอลัมน์ (Excel) | ข้อมูล | ตัวอย่าง | นำไปใช้ในระบบอย่างไร |
|---|---|---|---|
| `CANDIDATE NO` | รหัสประจำตัวผู้สอบ | `HK2024-0012` | บันทึกเข้าฐานข้อมูล (ช่วยระบุตัวตน / อ้างอิง) |
| `GRADE` | ระดับชั้น | `Primary 5`, `G.6` | บันทึกลงระดับชั้นของผู้เข้าสอบ |
| `CANDIDATE NAME` | ชื่อ-นามสกุล (อังกฤษ) | `SOMCHAI JAIDEE` | ใช้ Normalize เพื่อจับคู่กับชื่อบนเกียรติบัตร |
| `AWARD` | รางวัลที่ได้รับ | `Gold`, `Silver` | ใช้เป็นเงื่อนไขร่วมในการจับคู่ |

> **⚠️ ข้อเท็จจริงสำคัญมาก (Critical Fact):**
> **บนหน้าเกียรติบัตร PDF ไม่มี `CANDIDATE NO` ระบุอยู่** 
> ดังนั้นระบบไม่สามารถใช้เลขประจำตัวสอบในการจับคู่โดยตรงได้ ต้องจับคู่ผ่าน **`ชื่อ (Name)` + `รางวัล (Award)`** แทน

## 3. โครงสร้างแพ็กเกจไฟล์ที่แอดมินอัปโหลด (ZIP Intake Structure)

เพื่อให้ระบบรู้รางวัลของแต่ละไฟล์ PDF โดยอัตโนมัติ แอดมินจะจัดโครงสร้างไฟล์และบีบอัดเป็น `.zip` อัปโหลดเข้าระบบ:

```text
📦 HKIMO_Heat_2024.zip (หรือ HKIMO_Final_2024.zip)
 ├── 📁 gold/
 │    └── *.pdf          (ไฟล์ PDF รวมเล่มของเหรียญทอง)
 ├── 📁 silver/
 │    └── *.pdf          (ไฟล์ PDF รวมเล่มของเหรียญเงิน)
 ├── 📁 bronze/
 │    └── *.pdf          (ไฟล์ PDF รวมเล่มของเหรียญทองแดง)
 ├── 📁 merit/
 │    └── *.pdf          (ไฟล์ PDF รวมเล่มของรางวัลชมเชย)
 └── 📁 perfect score/
      └── *.pdf          (ไฟล์ PDF รวมเล่มของ Perfect Score)
```

* หมายเหตุ: ชื่อโฟลเดอร์ใน zip จะถูก normalize ให้เป็นค่าคงที่ของระบบ (เช่น `gold`, `silver`, `bronze`, `merit`, `perfect_score`)

## 4. รูปแบบการตั้งชื่อไฟล์หลังการตัดแยก (PDF Renaming Format)

ระบบจะทำการตัดแยก (Split) PDF รวมเล่มออกมาเป็นไฟล์เดี่ยว 1 หน้าต่อ 1 คน และเปลี่ยนชื่อไฟล์ให้อัตโนมัติ:

### รูปแบบชื่อไฟล์:
```text
{fname}_{lname}_{รายการสอบ}_{award}_{ปีที่สอบ}.pdf
```

### องค์ประกอบในชื่อไฟล์:
1. **`fname_lname`**: ชื่อและนามสกุลภาษาอังกฤษที่สกัดได้จากข้อความในหน้าเกียรติบัตร (แปลงเป็นตัวพิมพ์ใหญ่ และแทนช่องว่างด้วย `_`)
2. **`รายการสอบ`**: รหัสรายการสอบและรอบ เช่น `HKIMO_HEAT` หรือ `HKIMO_FINAL`
3. **`award`**: รางวัลที่ได้ ซึ่งได้มาจากชื่อโฟลเดอร์ย่อยใน zip (`GOLD`, `SILVER`, `BRONZE`, `MERIT`, `PERFECT_SCORE`)
4. **`ปีที่สอบ`**: ปี ค.ศ. ที่สกัดได้จากข้อความบนเกียรติบัตร เช่น `2024`

### ตัวอย่าง:
* `SOMCHAI_JAIDEE_HKIMO_HEAT_GOLD_2024.pdf`
* `PIYADA_SRISUK_HKIMO_FINAL_PERFECT_SCORE_2024.pdf`

## 5. ขั้นตอนการประมวลผลและการจับคู่ (Processing & Matching Workflow)

```
[ แอดมิน ]
   │
   ├─ 1. อัปโหลด ZIP เกียรติบัตร (แยกโฟลเดอร์ตามเหรียญ)
   │     │
   │     ▼
   │  [ Worker: Unzip & Split ]
   │     ├─ อ่าน Award จากชื่อโฟลเดอร์ (gold, silver, ...)
   │     ├─ สแกนข้อความในหน้า:
   │     │   ├─ รอบ Final: ตรวจ 'from THAILAND' (ถ้าไม่ใช่คนไทย -> ข้ามทันที)
   │     │   └─ รอบ Heat: ประมวลผลทุกหน้า
   │     ├─ ดึง ชื่อ (Name) + ปีการศึกษา (Year ค.ศ.)
   │     ├─ Rename & Split PDF รายคน + Render รูป Preview WebP
   │     └─ บันทึกลง staging_pages (เก็บชื่อ, award, level, raw text, file keys)
   │
   ├─ 2. อัปโหลด Excel รายชื่อ (CANDIDATE NO, GRADE, CANDIDATE NAME, AWARD)
   │     │
   │     ▼
   │  [ Worker: Match Excel ]
   │     ├─ อ่านแถวใน Excel: Normalize ชื่อ และ Normalize รางวัล
   │     ├─ จับคู่กับ staging_pages โดยใช้:
   │     │   1) Name ตรงกัน
   │     │   2) Award ตรงกัน
   │     └─ [ กฎกรณีชื่อซ้ำ ]:
   │         ├─ ถ้าชื่อเดียวกัน แต่ได้ "คนละรางวัล" -> บันทึกและเก็บทั้งสองรางวัล
   │         └─ ถ้าชื่อเดียวกัน และ "รางวัลเดียวกัน" ซ้ำซ้อน -> ส่งเข้า AMBIGUOUS ให้แอดมินตรวจ
   │
   └─ 3. แอดมินตรวจสรุป และกดเผยแพร่ (Publish) -> ผู้ปกครองค้นหาและดาวน์โหลดได้
```

## 6. กฎการจับคู่และการจัดการกรณีชื่อซ้ำ (Matching & Duplication Rules)

1. **คีย์หลักในการจับคู่ (Match Key):**
   * `normalized(CANDIDATE NAME)` + `normalized(AWARD)`
2. **กรณีผู้เข้าสอบชื่อเดียวกัน (Duplicate Student Names):**
   * **คนละรางวัล:** หากเด็ก 1 คนลงแข่งหลายประเภทหรือได้รับมากกว่า 1 รางวัล (เช่น ได้ทั้ง Gold ในหมวดหนึ่ง และ Perfect Score หรือได้ Merit เพิ่ม) -> **เก็บทั้งสองใบ** โดยสร้าง `Certificate` แยกรายการรางวัลให้ผู้เข้าสอบคนนั้น
   * **รางวัลเดียวกัน ซ้ำซ้อน:** หากชื่อเดียวกันและรางวัลเดียวกันโผล่ซ้ำในรอบเดียวกัน -> ถือเป็น `DUPLICATE_NAME` หรือ `AMBIGUOUS` ให้แอดมินเปิดดูหน้าจริงเพื่อยืนยัน (เช่น เป็นคนละคนที่มีชื่อพ้องกัน หรือเป็นไฟล์ที่เผลอใส่ซ้ำมา)

## 7. สิ่งที่ต้องปรับปรุงในระบบปัจจุบัน (System Adjustments Needed)

เพื่อให้รองรับสเปกใหม่ตามที่อธิบาย ระบบจะต้องปรับปรุงดังนี้:

1. **การอัปโหลดไฟล์ (Upload Component & Storage):**
   * เปลี่ยนจากการรับไฟล์ PDF รวมเล่ม 1 ไฟล์ เป็นการรับไฟล์ `.zip`
   * Worker ต้องเพิ่มความสามารถในการ Unzip และสำรวจโครงสร้าง Directory ภายใน
2. **การผูก Award ในขั้นตอน Split:**
   * บันทึกค่า `award` ลงใน `staging_pages` ตั้งแต่ขั้นตอน Split โดยอ่านจากชื่อ Folder ใน ZIP
   * สกัดปี ค.ศ. จากข้อความบนเกียรติบัตร เพื่อนำมาประกอบชื่อไฟล์
3. **การปรับปรุงฐานข้อมูล (Prisma Schema):**
   * เดิมที `Certificate` มีเงื่อนไข `@@unique([examId, studentId])` ซึ่งห้ามเด็ก 1 คนมีมากกว่า 1 ใบในรอบการสอบเดียวกัน
   * **ต้องปรับเป็น:** อนุญาตให้มีหลายใบได้หากเป็นคนละรางวัล หรือกำหนด unique ร่วมกับ `award` เช่น `@@unique([examId, studentId, award])` หรือใช้ `stagingPageId`
   * เพิ่มฟิลด์ `candidateNo` ลงในตาราง `Student` หรือ `Certificate`
4. **ตรรกะการ Match ใน Worker (`match_excel.py`):**
   * ปรับฟังก์ชันค้นหาให้เช็คเงื่อนไข `Name == Page.Name AND Award == Page.Award`
