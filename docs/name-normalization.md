# สเปกกลาง: กฎ Normalize ชื่อ

> **ไฟล์นี้คือแหล่งความจริงเดียว (single source of truth)**
> โค้ดมีสองภาษา — `apps/web/src/lib/normalize.ts` และ `apps/worker/app/normalize.py`
> ถ้าสองฝั่งให้ผลไม่ตรงกัน **การจับคู่ (match) จะพังแบบเงียบ ๆ** คือไม่ error แต่หาไม่เจอ
> ทั้งสองไฟล์ต้องผ่านชุดทดสอบเดียวกันที่ `shared/normalize-cases.json`

---

## ทำไมต้อง normalize

ชื่อคนเดียวกันมาจาก 3 แหล่งที่เขียนไม่เหมือนกัน:

| แหล่ง | ตัวอย่างที่เจอจริง |
|---|---|
| ข้อความใน PDF เกียรติบัตร | `Mr. Somchai   Jaidee` |
| Excel รายชื่อของเจ้าหน้าที่ | `SOMCHAI JAIDEE` |
| ช่องค้นหาที่ผู้ปกครองพิมพ์ | `somchai jaidee` |

ทั้งสามต้องถูกแปลงให้เหลือค่าเดียวกัน คือ `SOMCHAI JAIDEE`

---

## ฟังก์ชันที่ต้องมี 2 ตัว

### 1. `normalizeName(raw) -> string`
แปลงชื่อให้เป็นรูปมาตรฐาน **โดยคงลำดับคำไว้**

### 2. `nameSortKey(raw) -> string`
เรียกใช้ `normalizeName` ก่อน แล้ว**เรียงลำดับคำ (token) ตามตัวอักษร**
ใช้เป็นตัวช่วยจับคู่กรณี Excel เขียนสลับ `นามสกุล ชื่อ` ขณะที่ PDF เขียน `ชื่อ นามสกุล`

```
normalizeName("Jaidee Somchai")  -> "JAIDEE SOMCHAI"
normalizeName("Somchai Jaidee")  -> "SOMCHAI JAIDEE"     # คนละค่า
nameSortKey("Jaidee Somchai")    -> "JAIDEE SOMCHAI"
nameSortKey("Somchai Jaidee")    -> "JAIDEE SOMCHAI"     # ค่าเดียวกัน
```

> `nameSortKey` ใช้เป็น**ตัวช่วยลำดับรอง**เท่านั้น ห้ามใช้ยืนยันตัวตนเดี่ยว ๆ
> เพราะ `สมชาย ใจดี` กับ `ใจดี สมชาย` อาจเป็นคนละคนจริง ๆ

---

## ขั้นตอนของ `normalizeName` (ต้องทำตามลำดับนี้เป๊ะ)

### ขั้นที่ 1 — Unicode NFD → ลบ combining diacritic → NFC
1. แตกอักขระเป็นรูปย่อย (NFD)
2. ลบ combining mark ช่วง `U+0300–U+036F` ทิ้ง — ทำให้ `José` → `Jose`, `Müller` → `Muller`
3. ประกอบกลับเป็น NFC

ขั้นนี้จำเป็นเพราะภาษาไทยตัวเดียวกันเขียนได้หลาย byte sequence ถ้าไม่ทำ `"ก" != "ก"` ได้
วรรณยุกต์/สระไทยอยู่ช่วง `U+0E00–U+0E7F` **ไม่โดนลบ** เพราะอยู่คนละช่วงกับ `U+0300–U+036F`

### ขั้นที่ 2 — แทนอักขระที่ไม่ใช่ตัวอักษร/ตัวเลข ด้วยช่องว่าง
เก็บไว้เฉพาะ:
- ตัวอักษรละติน `A–Z` `a–z`
- ตัวเลข `0–9`
- อักขระไทย ช่วง `U+0E00–U+0E7F`

ที่เหลือ (จุด, ขีด, apostrophe, comma, tab, newline, non-breaking space `U+00A0`, zero-width `U+200B`, `U+FEFF`) → กลายเป็นช่องว่างทั้งหมด

ผลข้างเคียงที่ยอมรับ: `O'Brien` → `O BRIEN`, `Anne-Marie` → `ANNE MARIE`
ไม่เป็นไรเพราะ**ทั้งสองฝั่งทำเหมือนกัน** จึงยังจับคู่กันได้

หมายเหตุ: อักขระละตินที่แตก NFD ไม่ได้ (เช่น `ø`, `đ`, `ß`) จะกลายเป็นช่องว่างในขั้นนี้

### ขั้นที่ 3 — ยุบช่องว่างซ้ำ + ตัดหัวท้าย
`"  Somchai    Jaidee  "` → `"Somchai Jaidee"`

### ขั้นที่ 4 — ทำเป็นตัวพิมพ์ใหญ่
`.upper()` / `.toUpperCase()` — ไม่กระทบตัวอักษรไทย

### ขั้นที่ 5 — ตัดคำนำหน้าชื่อ (วนซ้ำจนกว่าจะไม่มีอะไรถูกตัด สูงสุด 3 รอบ)

**คำนำหน้าภาษาไทย** — ตัดแบบ "ขึ้นต้นด้วย" ไม่ต้องมีช่องว่างคั่น
เพราะภาษาไทยเขียนติดกัน เช่น `นายสมชาย`

เรียงจากยาวไปสั้น (สำคัญมาก ไม่งั้น `นางสาว` จะโดน `นาง` ตัดก่อน):
```
เด็กหญิง  เด็กชาย  นางสาว  ว่าที่ร้อยตรี  นาง  นาย  ด ช  ด ญ  น ส  ดช  ดญ  นส
```
(`ด.ช.` กลายเป็น `ด ช` ไปแล้วตั้งแต่ขั้นที่ 2)

**คำนำหน้าภาษาอังกฤษ** — ตัดแบบ "เป็นคำแรก" **ต้องมีช่องว่างตามหลัง**
```
MR  MRS  MS  MISS  MASTER  DR  PROF
```
> เงื่อนไข "ต้องมีช่องว่างตามหลัง" จำเป็น ไม่งั้นชื่อจริงอย่าง `MRINAL` จะถูกตัดเหลือ `INAL`
> ส่วนภาษาไทยไม่ต้องมีเงื่อนไขนี้ เพราะไม่เขียนเว้นวรรคระหว่างคำ

### ขั้นที่ 6 — ยุบช่องว่าง + ตัดหัวท้าย อีกรอบ
เพราะขั้นที่ 5 อาจทิ้งช่องว่างไว้ข้างหน้า

## ข้อจำกัดที่รู้อยู่ (accepted trade-off)

1. ชื่อไทยที่**ขึ้นต้นด้วย** `นส` `ดช` `ดญ` จริง ๆ จะถูกตัดผิด — แทบไม่มีในทางปฏิบัติ แต่ถ้าเจอให้ลบออกจากลิสต์
2. ยศ/ตำแหน่งอื่น (พ.ต.ท., ศ.ดร., ร.ต.อ.) ยังไม่รองรับ — ผู้เข้าสอบเป็นนักเรียน จึงไม่จำเป็น
3. ไม่แก้คำสะกดผิดหรือทำ fuzzy matching — งานนั้นเป็นหน้าที่ของ `pg_trgm` ตอนค้นหา ไม่ใช่ตอน normalize
