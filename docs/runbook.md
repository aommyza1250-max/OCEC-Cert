# คู่มือแก้ปัญหา

> ถ้ากำลังหาว่า "จะเพิ่มข้อมูลยังไง" ให้ดู [admin-guide.md](admin-guide.md) แทน
> ไฟล์นี้ใช้ตอนระบบมีปัญหา และสำหรับงานดูแลระบบที่ต้องสั่งเอง

## ต้นทางส่งเกียรติบัตรมาไม่ครบ แล้วส่งตามมาทีหลัง

เป็นเรื่องที่เจอบ่อยที่สุด ให้ **เติมเข้ารอบนำเข้าเดิม ไม่ต้องสร้างรอบใหม่**

1. **หาว่าใครตกหล่น** — ดูหัวข้อ **"ผู้เข้าสอบที่ยังไม่มีเกียรติบัตร"** ในหน้ารอบนำเข้า
   รายการนี้มีเลขผู้เข้าสอบ ชื่อ รูปแบบการสอบ และรางวัลตาม Excel ส่งให้ต้นทางได้เลย
   คนที่มีแค่ใบรางวัลเสริม (เช่น Perfect Score) แต่ยังไม่มีใบรางวัลหลักก็อยู่ในรายการนี้ด้วย
2. **ถ้าเผยแพร่อยู่ ต้องยกเลิกการเผยแพร่ก่อน** ระหว่างเผยแพร่ ระบบจะไม่ให้อัปไฟล์
   ให้เตรียมไฟล์ให้พร้อมก่อนกดยกเลิก เพราะระหว่างนั้นผู้ปกครองจะค้นหาใครในรอบนี้ไม่เจอเลย
3. **อัปไฟล์**
   - ไม่กี่คน: เลือกรางวัล แล้วอัป PDF ในแถวของคนนั้น (ไฟล์รวมเล่มก็ได้ ระบบคัดเฉพาะหน้าของคนนั้น)
   - หลายคน: อัป ZIP ตามโครง `online/<รางวัล>/` `onsite/<รางวัล>/` จะอัปชุดเต็มทั้งก้อนก็ได้
     เพราะระบบข้ามใบที่มีอยู่แล้วให้ โดยดูจาก **เลขผู้เข้าสอบคู่กับรางวัล**
4. **ตรวจผล** — ดูที่ "ประวัติการอัป" ว่า `หน้าใหม่` และ `ข้าม (มีใบแล้ว)` สมเหตุสมผล
   แล้วดูว่ารายการผู้เข้าสอบที่ยังไม่มีเกียรติบัตรลดลง
5. **เผยแพร่อีกครั้ง**

## อัปไฟล์ของคนที่ตกหล่นแล้วระบบไม่รับ

ข้อความจะขึ้นในแถวของคนนั้น มี 3 แบบ

| ข้อความ | สาเหตุ | แก้โดย |
|---|---|---|
| "ชื่อบนเกียรติบัตรตรงกับผู้เข้าสอบคนนี้แล้ว แต่เลขบนหน้าเป็น ..." | เลขบนหน้าไม่ตรงกับรายชื่อ มักเกิดจากการแก้ไฟล์เอง | ขอไฟล์ที่ถูกจากต้นทาง ถ้ารายชื่อผิด ให้แก้เลขในหน้าผู้เข้าสอบ |
| "ไฟล์นี้ไม่มีหน้าของผู้เข้าสอบเลข ... — ในไฟล์พบ: ..." | หยิบไฟล์ผิดคน | ข้อความบอกว่าไฟล์นั้นเป็นของใคร ให้อัปในแถวของคนนั้นแทน |
| "... ระบบแยกไม่ออกว่าหน้าไหนคือใบที่ต้องการ" | ในไฟล์มีหน้าของคนนี้หลายใบ | แยกใบที่ต้องการออกมาเป็น PDF หน้าเดียวแล้วอัปใหม่ |

**ทุกแบบไม่ทำให้ข้อมูลเสียหาย** ระบบตรวจก่อนนำเข้า จึงไม่มีไฟล์ขยะค้าง และไม่แตะของเดิม

## อัป ZIP แล้วขึ้นว่า "โครงสร้างไฟล์ ZIP ไม่ถูกต้อง จึงยังไม่นำเข้าอะไรเลย"

ระบบตรวจทั้ง ZIP ก่อนตัดหน้าแรก ถ้าเจอปัญหาแม้แต่ข้อเดียวจะไม่รับทั้งไฟล์ และข้อมูลเดิมไม่ถูกแตะเลย
ข้อความจะแสดงปัญหาทุกข้อพร้อมตัวอย่างไฟล์ แก้ตามนี้แล้วบีบอัดใหม่:

- **ไม่ได้อยู่ในโฟลเดอร์ online หรือ onsite** → โครงเก่า (`gold/*.pdf`) ใช้ไม่ได้แล้ว
  ต้องเป็น `online/<รางวัล>/*.pdf` หรือ `onsite/<รางวัล>/*.pdf`
- **โฟลเดอร์ที่ไม่รู้ว่าเป็นรางวัลอะไร** → ชื่อโฟลเดอร์ไม่ตรงกับรายการที่รอบนั้นรับ
  รายการที่รับได้แสดงอยู่ในหน้าอัปโหลด และอยู่ใน `shared/certificate-profiles/<รายการ>.json`
  ระบบตั้งใจหยุดแทนการเดา เพราะถ้ารางวัลผิด หน้าเว็บของเด็กก็จะแสดงรางวัลผิด
- **รางวัลที่ไม่มีในรอบนี้** → เช่น `Participation` ในรอบ Final ให้ตรวจว่าเลือกรอบนำเข้าถูกไหม
- **ไฟล์ที่เป็นเกียรติบัตรของรอบหรือปีอื่น** → หยิบไฟล์ผิดชุด
- **มีโฟลเดอร์ครอบชั้นนอกหลายชื่อ / ซ้อนลึกเกินหนึ่งชั้น** → บีบอัดใหม่ให้มีโฟลเดอร์ครอบไม่เกิน 1 ชั้น

ถ้าต้นทางใช้ชื่อโฟลเดอร์รางวัลแบบใหม่ที่ถูกต้องจริง (เช่น ชื่อรางวัลใหม่ของปีนั้น)
ต้องให้คนเขียนโค้ดเพิ่มชื่อนั้นใน manifest แล้ว deploy ก่อน ดู [certificate-profiles.md](certificate-profiles.md)
**ห้ามแก้ด้วยการเปลี่ยนชื่อโฟลเดอร์ให้เป็นรางวัลอื่นที่ระบบรู้จัก**

## อัปรายชื่อแล้วระบบไม่รับ

ระบบตรวจทั้งไฟล์ก่อน และแสดงแถวที่ผิดทั้งหมดในครั้งเดียว ระหว่างนั้นรายชื่อชุดที่ใช้อยู่ไม่ถูกแตะ

- **ไม่มีคอลัมน์ EXAM MODE** → ต้องเพิ่มคอลัมน์รูปแบบการสอบ ค่าในคอลัมน์ต้องเป็น `ONLINE` หรือ `ONSITE`
- **เลขผู้เข้าสอบซ้ำกัน** → เลขเดียวกันจะมีทั้งใน online และ onsite ไม่ได้ ให้ต้นทางยืนยันว่าคนนั้นสอบแบบไหน
- **เลขผู้เข้าสอบต้องเป็นตัวเลขล้วน** → มักเป็นช่องที่มีตัวอักษรหรือช่องว่างติดมา

## กด "ใช้รายชื่อชุดนี้" แล้วขึ้นว่ามีรายการชนกัน

ร่างรายชื่อมีแถวที่ชนกับผู้เข้าสอบที่แอดมินเพิ่มเอง (เลขเดียวกัน หรือชื่อเดียวกันแต่เลขต่างกัน)
ต้องตัดสินทุกรายการก่อน: รวมเป็นคนเดียวกัน หรือเก็บรายการที่เพิ่มเองไว้แล้วไม่ใช้แถวนั้น

ถ้ามีคนเพิ่มผู้เข้าสอบเองระหว่างที่คุณกำลังตัดสิน ระบบจะแจ้งว่ารายการชนกันเปลี่ยนไปแล้ว
ให้รีเฟรช แล้วตัดสินใหม่ตามรายการล่าสุด

## เผยแพร่ไม่ได้ ระบบให้เลือกก่อน

รอบที่มีผู้เข้าสอบได้ทั้งรางวัลหลักและรางวัลเสริม (เช่น Gold + Perfect Score หรือ Special Award)
ต้องเลือกก่อนว่าต้นทางส่งฉบับจริงมาแบบไหน

- **ทุกใบ** — ผู้ปกครองเห็นทั้งใบรางวัลหลักและใบรางวัลเสริม
- **เฉพาะใบรางวัลหลัก** — ใบรางวัลเสริมของคนที่มีใบหลักจะถูกซ่อน (ยังอยู่ในระบบ ไม่ได้ลบ)

ถ้าเลือกผิด ให้ยกเลิกการเผยแพร่ เลือกใหม่ แล้วเผยแพร่อีกครั้ง

## บางคนไม่ถูกเผยแพร่

ระบบเผยแพร่ **ทีละคน** คนที่ข้อมูลครบจะออกไปก่อน ส่วนคนที่ยังมีปัญหาจะค้างไว้
แผงเผยแพร่แสดงจำนวนคนที่ค้างไว้ แยกตามเหตุผลและตาม online/onsite

| เหตุผล | แก้โดย |
|---|---|
| ยังไม่มีไฟล์เกียรติบัตร | อัปไฟล์ของคนนั้น |
| มีแต่ใบรางวัลเสริม ใบรางวัลหลักยังไม่มา | ขอใบรางวัลหลักจากต้นทาง รางวัลเสริมให้คู่กับรางวัลหลักเสมอ ถ้าปล่อยใบเสริมออกไปก่อน ผู้ปกครองจะเข้าใจผิดว่านั่นคือรางวัลที่ได้ |
| ชื่อไม่ตรง / online/onsite ไม่ตรง / ระบุตัวไม่ได้ / ใบซ้ำ / รอยืนยันสัญชาติ / รอบ/ปีไม่ตรง | ตัดสินในหัวข้อ "หน้าที่ต้องตัดสิน" |

แก้แล้วต้อง **เผยแพร่อีกครั้ง** ระบบไม่เผยแพร่ให้เองโดยอัตโนมัติ

## ผู้ปกครองบอกว่าค้นชื่อไม่เจอ

ไล่ตามลำดับนี้:

1. **รอบนั้นเผยแพร่อยู่ไหม** — ถ้ามีคนกดยกเลิกการเผยแพร่ไว้ ทั้งรอบจะค้นไม่เจอ
2. **คนนั้นถูกค้างไว้หรือเปล่า** — ค้นชื่อในหน้า "ค้นหาและแก้ไขผู้เข้าสอบ" แล้วดูว่ามีปัญหาค้างอยู่ไหม
   ถ้าเป็นใบรางวัลเสริม ให้ดูด้วยว่ารอบนั้นตั้งไว้ว่าเผยแพร่เฉพาะใบรางวัลหลักหรือเปล่า
3. **ไฟล์ถูกลบเพราะครบอายุแล้วหรือยัง** — หน้ารอบนำเข้าบอกจำนวนใบที่ไฟล์ถูกลบไปแล้ว
4. **ชื่อในระบบสะกดตรงกับที่ผู้ปกครองพิมพ์ไหม**
   ```sql
   SELECT name_th, name_en, name_th_normalized, name_en_normalized
   FROM students WHERE name_en_normalized LIKE '%SOMCHAI%';
   ```
   ถ้าคอลัมน์ normalized ว่างหรือหน้าตาแปลก แปลว่ามีอักขระที่กฎ normalize จัดการไม่ได้ (ดู [name-normalization.md](name-normalization.md))

## ขึ้นว่า "รอให้ระบบประมวลผลเสร็จก่อน" นานผิดปกติ

ระหว่างที่มีงานตรวจรายชื่อ ใช้รายชื่อ ตัดหน้า หรือจับคู่ค้างอยู่ ระบบจะไม่ให้แก้รอบนั้น (กันการแก้ทับกัน)

```sql
SELECT id, type, status, attempts, error, locked_at, created_at
FROM jobs WHERE batch_id = '<batch id>' ORDER BY created_at DESC LIMIT 10;
```

- **QUEUED นาน** → worker ไม่ทำงาน ดู `docker compose logs worker` หรือ log ของ Railway
  worker จะไม่หยิบงานของรอบที่ยังมีงาน RUNNING ค้างอยู่ งานถัดไปของรอบเดียวกันจึงรอจนกว่างานนั้นจบ
- **RUNNING แต่ `locked_at` เก่ามาก** → worker ตายกลางงาน ให้ส่งกลับเข้าคิว:
  ```sql
  UPDATE jobs SET status = 'QUEUED', locked_at = NULL
  WHERE id = '<job id>' AND status = 'RUNNING';
  ```
  งานทุกชนิดรันซ้ำได้อย่างปลอดภัย งานตัดหน้าที่ล้มเหลวจะถูกย้อนกลับก่อนเริ่มใหม่
- **FAILED** → อ่านคอลัมน์ `error` จะมี traceback เต็ม
  - งานตัดหน้า (SPLIT) ที่ล้มเหลวถูกย้อนกลับเองแล้ว หน้าที่งานนั้นสร้างและไฟล์ใต้ `certificates/<batch>/<job>/` ถูกลบ
    ส่วนหน้าเก่าที่ถูกแทนไปจะได้สถานะเดิมคืน ZIP ต้นฉบับยังอยู่ให้ตรวจสาเหตุ
  - งานใช้รายชื่อ (ROSTER_ACTIVATE) ทำใน transaction เดียว ถ้าล้มเหลว รายชื่อชุดเดิมยังใช้อยู่ครบ
    และร่างกลับไปเป็นพร้อมใช้ ให้กดใช้ใหม่ได้

## จับคู่ผิดคน (เรื่องด่วน)

1. **ยกเลิกการเผยแพร่รอบนั้นทันที** เพื่อหยุดไม่ให้ใครดาวน์โหลดได้อีก
2. เปิดหน้าผู้เข้าสอบคนนั้น แล้วดูที่ "การแก้ไขล่าสุด" ว่าเกิดจากการตัดสินด้วยมือหรือจากรายชื่อ
   - ถ้ารายชื่อผิด ให้แก้ Excel แล้วอัปใหม่ หรือแก้ในหน้าผู้เข้าสอบ ระบบจะจับคู่ใหม่ให้เอง
   - ถ้าตัวคนถูกผูกผิด (รวมคนสองคนเป็นคนเดียว) ให้กด **"ผูกผิดคน — แยกเป็นคนใหม่"**
   - ถ้าหน้าเป็นของคนอื่น ให้ทิ้งหน้านั้น แล้วอัปไฟล์ที่ถูกให้เจ้าของตัวจริง
3. ตรวจยอดในแผงเผยแพร่ แล้วค่อยเผยแพร่อีกครั้ง

## ตัดหน้าแล้วได้จำนวนไม่ตรงกับไฟล์

ดูตัวเลขใน "ประวัติการอัป" ของไฟล์นั้น:

- **ต่างชาติ (ข้าม) สูงผิดปกติ** → ถ้าเป็นรอบ Heat แปลว่าเลือกรอบนำเข้าผิด เพราะรอบ Heat ไม่ควรข้ามใครเลย
- **รอยืนยันสัญชาติ สูง** → แบบฟอร์มของรอบ Final ปีนี้ไม่มีบรรทัด `from <ประเทศ>` ในตำแหน่งที่โปรไฟล์รู้จัก
  รันสำรวจด้วย `docker compose exec worker python scripts/check_real_files.py`
  แล้วปรับโปรไฟล์ของรายการนั้นใน `apps/worker/app/certificate_profiles/` (ไม่มี env ให้ตั้งแล้ว)
- **ข้อความรางวัลไม่ตรงโฟลเดอร์ ไม่เป็น 0** → มีไฟล์วางผิดโฟลเดอร์รางวัล ให้ตรวจ ZIP ต้นทาง
  ถ้ามีแค่ไม่กี่ใบ ให้แก้ด้วยการเปลี่ยนรางวัลในหน้าผู้เข้าสอบ
- **ข้าม (หน้าเดิมที่เคยอัป) หรือ ข้าม (มีใบแล้ว) สูง** → ปกติ ถ้าอัปชุดเต็มซ้ำ

> หน้า Perfect Score ไม่มีข้อความรางวัลพิมพ์อยู่ จึงไม่นับเป็นรางวัลไม่ตรง

## หน้าขึ้นว่า "มีผู้เข้าสอบชื่อนี้อยู่ในระบบแล้ว และระบบแยกไม่ออกว่าเป็นคนไหน"

ระบบเจอคนชื่อเดียวกันจากรายการหรือปีอื่นหลายคน แล้วแยกไม่ออก จึงไม่เดาให้
(การสร้างคนใหม่ก็นับเป็นการเดาเหมือนกัน ถ้าเดาผิด เกียรติบัตรของคนคนเดียวจะแยกไปอยู่สองที่)

เปิดหน้าผู้เข้าสอบคนนั้น แล้วเลือกคนเดิมโดยดูจากโรงเรียนและเกียรติบัตรที่มีอยู่ หรือกด **"คนใหม่ ไม่ใช่คนใดข้างบน"**

## รอบที่ขึ้นว่า "รอบนี้มาจากระบบเดิม"

รอบที่นำเข้าก่อนเปลี่ยนมาใช้ขั้นตอนใหม่ ยังไม่มีรายชื่อ online/onsite และยังไม่มีโปรไฟล์
รอบแบบนี้ยังเผยแพร่ต่อได้ตามปกติ แต่ **อัปไฟล์ แก้ไข หรือเผยแพร่ใหม่ไม่ได้**
ถ้าต้องแก้ ให้ทำตามหัวข้อถัดไป

## นำข้อมูลชุดเดิมเข้าใหม่ตามขั้นตอนใหม่

งานนี้ **ไม่ได้ทำอัตโนมัติตอน deploy** migration ของขั้นตอนใหม่เพิ่มตารางและคอลัมน์อย่างเดียว ไม่ลบข้อมูลเดิมเลย
ทุกขั้นข้างล่างต้องมีคนสั่งเอง และต้องได้รับการยืนยันจากเจ้าของระบบก่อนเริ่มขั้นที่ 3

### 1. เตรียมไฟล์ใหม่ให้พร้อมก่อน

- **Excel รายชื่อชุดรวม** ที่มีคอลัมน์ `EXAM MODE` ครบทุกแถว
- **ZIP เกียรติบัตร** จัดโครงใหม่เป็น `online/<รางวัล>/` และ `onsite/<รางวัล>/`

ไม่ต้องสร้างรอบนำเข้าบนระบบจริงเพื่อลองไฟล์ ให้ลองกับ dev ในเครื่องก่อน แล้วเทียบยอดให้ตรงกับที่ต้นทางแจ้ง
ก่อนเริ่มขั้นที่ 3 ไฟล์ต้องผ่านการตรวจรายชื่อและตรวจโครงสร้าง ZIP ครบแล้ว

### 2. สำรองข้อมูลเดิม (อ่านอย่างเดียว)

```bash
docker compose exec worker python scripts/backup_batch.py --list                 # ดู id ของรอบที่จะสำรอง
docker compose exec worker python scripts/backup_batch.py <batch id> --with-files
```

บน Railway ให้รันคำสั่งเดียวกันใน shell ของ service `worker`
แล้วสำรองทั้งฐานข้อมูลด้วย `pg_dump` อีกชั้น:

```bash
pg_dump "$DATABASE_URL" --format=custom --file=ocec-before-reimport-$(date +%Y%m%d).dump
```

ตรวจ `summary.txt` ว่า **"ฐานข้อมูลอ้างถึงแต่ไม่พบบน R2: 0 ไฟล์"** และจดยอดไว้เทียบในขั้นที่ 5

> ⚠️ ไฟล์สำรองมีชื่อและเกียรติบัตรของคนจริง ห้าม commit เข้า git
> เก็บไว้ในที่ที่ปลอดภัย แล้วลบออกจากเครื่องที่ใช้ทำงาน

### 3. ลบรอบเดิม (ต้องได้รับการยืนยันก่อน)

ใช้ปุ่ม **"ลบรอบการนำเข้านี้"** ในโซนอันตรายท้ายหน้ารอบนำเข้า (ต้องพิมพ์ชื่อรอบเพื่อยืนยัน)
**อย่าใช้ `DELETE FROM batches` ตรง ๆ** เพราะไฟล์บน R2 จะไม่ถูกลบตาม และตัวคนที่ไม่เหลืออะไรแล้วจะค้างอยู่

ปุ่มนี้ลบเฉพาะไฟล์ใต้ `certificates/<batch id>/`, `previews/<batch id>/` และ `sources/<batch id>/`
ลบตัวคนเฉพาะคนที่ไม่เหลืออะไรในรอบอื่นชี้มาหา และเก็บบันทึกการแก้ไขไว้
ก่อนกดยืนยัน ให้ตรวจชื่อรอบและตัวเลขที่ระบบบอกว่าจะลบ ว่าตรงกับรอบที่สำรองไว้ในขั้นที่ 2

### 4. นำเข้าใหม่ตามขั้นตอนปกติ

ทำตาม [admin-guide.md](admin-guide.md) ข้อ 1:
สร้างรอบนำเข้า → อัปรายชื่อ → ใช้รายชื่อชุดนี้ → อัป ZIP → จัดการสิ่งที่ค้างไว้

### 5. เทียบยอดก่อนเผยแพร่

| เทียบ | กับ |
|---|---|
| ยอดรายชื่อ ทั้งหมด / Online / Onsite | ยอดที่ต้นทางแจ้ง |
| จำนวนเกียรติบัตรแยกตามรางวัล | `summary.txt` ของขั้นที่ 2 (ต่างกันได้เฉพาะส่วนที่อธิบายได้ เช่น ใบที่ตกหล่นในชุดเดิม) |
| จำนวนคนที่ถูกค้างไว้ และเหตุผล | ต้องอธิบายได้ทุกคน |
| สุ่มดาวน์โหลดจากหน้าค้นหาสาธารณะ | ไฟล์เปิดได้ ชื่อและรางวัลถูกต้อง อย่างน้อยทุกรางวัลและทั้ง online/onsite |

ถ้ายอดตรงแล้วจึงเผยแพร่ ถ้าไม่ตรงและหาสาเหตุไม่ได้ ห้ามเผยแพร่ ข้อมูลเดิมยังกู้คืนได้จากไฟล์สำรองในขั้นที่ 2

## ผู้ใช้กดดาวน์โหลดแล้วได้ Access Denied

presigned URL มีอายุ 15 นาที ถ้าผู้ใช้เปิดหน้าค้างไว้นานแล้วค่อยกด ให้รีเฟรชหน้าใหม่
ถ้าเกิดกับทุกคนทันทีที่กด แปลว่า credential ของ R2 ผิดหรือหมดอายุ

## แอดมินถูกเด้งออกจากระบบหลัง deploy

ปกติ เพราะคุกกี้ล็อกอินมีรหัสการล็อกอิน (session id) ไว้บันทึกการแก้ไข คุกกี้แบบเก่าจึงใช้ไม่ได้แล้ว
ให้ล็อกอินใหม่ครั้งเดียว

## ต้องลบข้อมูลของรอบนำเข้าทิ้งทั้งรอบ

ใช้ปุ่มในโซนอันตรายท้ายหน้ารอบนำเข้า (ดูขั้นที่ 3 ของหัวข้อข้างบน) ถ้าต้องการเก็บข้อมูลไว้ก่อน ให้สำรองด้วย `scripts/backup_batch.py` ก่อน

> ZIP ต้นฉบับใน `sources/` มีขนาดหลายร้อย MB ต่อรอบ ระบบลบให้เองหลังเผยแพร่และไม่มีอะไรค้างแล้ว
> ดูเหตุผลที่ยังลบไม่ได้ในหัวข้อ "ไฟล์ต้นฉบับ" ท้ายหน้ารอบนำเข้า

## ตรวจว่าระบบยังรับโหลดได้ไหม

```bash
BASE_URL=https://<โดเมนจริง> k6 run scripts/loadtest.js
```
เกณฑ์ผ่าน: p95 < 500ms, error rate < 1%
ถ้าไม่ผ่าน จุดแรกที่ต้องดูคือ index trigram บนตาราง `students` ยังอยู่ครบไหม:
```sql
SELECT indexname FROM pg_indexes WHERE tablename = 'students';
```
