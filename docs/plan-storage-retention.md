## งานที่ 1 — ลดขนาดรูปตัวอย่าง

### ตัวเลขที่วัดได้จากหน้าเกียรติบัตรจริง

| DPI | quality | ขนาดภาพ | ไฟล์ |
|---|---|---|---|
| 110 | 80 | 1286×909 | 242 KB ← ใช้อยู่ |
| **72** | **75** | **841×595** | **85 KB** ← เป้าหมาย |
| 60 | 72 | 701×496 | 57 KB |

841px คือความกว้างจริงของกระดาษ A4 นอน มือถือจอ 390px แสดงที่ 2 เท่าพอดี
กดดูเต็มจอยังอ่านชื่อและเลขได้ครบ คนที่อยากได้คมชัดกว่านั้นมีปุ่มโหลด PDF ตัวเต็มอยู่แล้ว

### ผลที่ได้

หน้าผลค้นหาของคนที่มี 4 ใบ: จาก 968 KB เหลือ 340 KB

### สิ่งที่ต้องทำ

1. `apps/worker/app/config.py` — เปลี่ยนค่าตั้งต้นเป็น `preview_dpi=72`, `preview_quality=75`
2. ตั้ง `PREVIEW_DPI=72` และ `PREVIEW_QUALITY=75` บน Railway service `worker`
3. `apps/worker/scripts/rerender_previews.py` (ใหม่) — อ่าน PDF ใบเดี่ยวจาก R2 มาเรนเดอร์รูปใหม่ทับ
   รับ `--batch <id>` และ `--dry-run` ใช้กับรอบที่นำเข้าไปแล้ว
4. แก้ `docs/architecture.md` ให้ตรง

### จังหวะ

**ทำก่อนนำเข้ารอบจริง** ตอนนี้ production ยังไม่มีข้อมูลเผยแพร่สักใบ ถ้าตั้งค่าก่อนก็ไม่ต้องรัน re-render เลย
สคริปต์ข้อ 3 ยังต้องเขียนไว้อยู่ดี เผื่อวันหน้าอยากปรับขนาดอีก

## งานที่ 2 — ลบ ZIP ต้นฉบับเมื่อจับคู่ครบ

### ทำไมตอนนี้ระบบยังเก็บ ZIP ไว้

สามเหตุผลตอนออกแบบ และสถานะจริงของแต่ละข้อวันนี้:

| เหตุผลตอนนั้น | จริงแค่ไหนวันนี้ |
|---|---|
| เผื่อ "ตัดใหม่ทั้งรอบ" โดยไม่ต้องขอไฟล์จากต้นทางใหม่ | **ไม่ได้ใช้จริง** — ปุ่มตัดใหม่ทั้งรอบบังคับให้อัป ZIP ใหม่อยู่แล้ว โค้ดที่อ่าน `source_zip_key` เหลือเป็นทางสำรองที่ไม่มี UI ไหนเรียก |
| เผื่อย้อนดูต้นฉบับตอนสงสัยว่าตัดหน้าผิด | จริง แต่**ไม่มีหน้าจอให้แอดมินโหลดกลับมาดู** ต้องเข้า Cloudflare เอง |
| เก็บเป็นหลักฐานว่าได้รับไฟล์อะไรมา | จริง แต่ไฟล์ต้นฉบับยังอยู่ในเครื่องแอดมินที่อัปขึ้นมาอยู่แล้ว R2 ไม่ใช่สำเนาเดียว |

สรุป: **ZIP ที่เก็บไว้ไม่มีอะไรในระบบเรียกใช้เลย** เป็นแค่กองไฟล์นิ่ง ๆ ที่กินที่มากที่สุด (360 MB ต่อรอบ)
เทียบกับเกียรติบัตร + รูปตัวอย่างรวมกันแค่ 210 MB

### สิ่งที่จะเสียไปถ้าลบ

เสียอย่างเดียวคือ **การตัดหน้าใหม่จากต้นฉบับโดยไม่ต้องอัปไฟล์ใหม่**
ซึ่งจะต้องใช้ก็ต่อเมื่อพบว่าตัวตัดหน้าทำงานผิดพลาดหลังจากจับคู่เสร็จแล้ว

แต่หน้าที่ตัดได้ทั้งหมด **ถูกเก็บเป็น PDF ใบเดี่ยวบน R2 ไปแล้ว** ทั้งใบที่จับคู่ได้และจับคู่ไม่ได้
สิ่งเดียวที่ไม่ได้เก็บคือหน้าที่ถูกข้ามเพราะเป็นของต่างชาติ (`SKIPPED_FOREIGN`)
ซึ่งเป็นเหตุผลที่เงื่อนไข "จับคู่ครบ" ต้องรัดกุม — ดูหัวข้อถัดไป

### เงื่อนไข "ครบ" ที่ปลอดภัยพอจะลบได้

ต้องเป็นจริง **ทุกข้อ** ถึงจะลบ:

1. ทุกแถวในชีทรายชื่อจับคู่ได้หมด (ไม่มีแถวไหนไม่มีเกียรติบัตร)
2. ไม่มีหน้าที่ค้างสถานะ `UNMATCHED` / `AMBIGUOUS` / `DUPLICATE_NAME`
3. รายการ "ต้องตามเก็บ" ว่างเปล่า (ใช้ `loadMissingItems()` ที่มีอยู่แล้วเป็นตัวตัดสิน)
4. รอบนำเข้านั้น **เผยแพร่แล้ว**

ข้อ 1 คือหัวใจ: ถ้าทุกคนในชีทมีเกียรติบัตรครบ แปลว่าไม่มีคนไทยคนไหนตกหล่น
หน้าที่ถูกข้ามไปจึงเป็นของต่างชาติจริง ๆ ไม่ใช่คนไทยที่อ่านสัญชาติผิด — ZIP จึงไม่เหลืออะไรที่เรายังต้องการ

### รอกี่วันก่อนลบ

**ตัดสินใจแล้ว: `SOURCE_ZIP_KEEP_DAYS=0` ลบทันทีที่ครบเงื่อนไขทั้ง 4 ข้อ**

ยังทำเป็นตัวแปรไว้ เผื่อวันหนึ่งอยากเปลี่ยนใจให้รอสักสัปดาห์โดยไม่ต้องแก้โค้ด
ถ้าต้องตัดหน้าใหม่จริงหลังลบไปแล้ว ให้อัป ZIP ขึ้นมาใหม่จากเครื่องแอดมิน
(ต้นฉบับยังอยู่ที่นั่นเสมอ R2 ไม่ใช่สำเนาเดียว)

### สิ่งที่จะลบและไม่ลบ

| ไฟล์ | ลบไหม | เพราะ |
|---|---|---|
| `sources/<batch>/bundle-*.zip` | **ลบ** | ก้อนใหญ่ที่สุด ไม่มีอะไรเรียกใช้ |
| `sources/<batch>/missing-*.pdf` | **ลบ** | ไฟล์ที่โยนเข้ามาทีละใบ ถูกแปลงเป็นใบเดี่ยวไปแล้ว |
| `sources/<batch>/roster.xlsx` | **เก็บ** | 5 KB เท่านั้น และใช้จับคู่ใหม่ได้โดยไม่ต้องขอไฟล์ใหม่ |
| `certificates/` `previews/` | **เก็บ** | คือของที่ผู้ปกครองใช้จริง |

### สิ่งที่ต้องทำ

1. เพิ่มคอลัมน์ `sources_cleared_at` ใน `batches` (รู้ว่าเคลียร์ไปแล้วเมื่อไหร่ ไม่ใช่แค่หายไปเฉย ๆ)
2. worker: งาน `CLEANUP_SOURCES` ตรวจเงื่อนไข 4 ข้อ แล้วลบไฟล์ใน `sources/` ยกเว้น `roster.xlsx`
   ตั้งคิวอัตโนมัติหลังงานจับคู่จบ และตรวจซ้ำวันละครั้งสำหรับรอบที่เพิ่งครบเงื่อนไขทีหลัง
3. หน้าแอดมินแสดงว่า "เคลียร์ไฟล์ต้นฉบับแล้วเมื่อ ..." พร้อมเหตุผลสั้น ๆ
   และถ้ายังไม่เคลียร์ ให้บอกว่าติดเงื่อนไขข้อไหนอยู่
4. ปุ่ม "เคลียร์เดี๋ยวนี้" สำหรับแอดมินที่มั่นใจแล้ว (ยังต้องผ่านเงื่อนไข 4 ข้อเหมือนกัน)

## งานที่ 3 — อายุการเก็บเกียรติบัตร 2 ปี

### หลักการ

ครบ 2 ปีนับจาก **วันเผยแพร่** → ลบไฟล์ PDF และรูปตัวอย่างบน R2
→ เหลือแถวในฐานข้อมูลไว้ (รู้ว่าเคยออกใบอะไรให้ใคร) → ผู้ปกครองค้นไม่เจออีก

### ฐานข้อมูล

เพิ่มใน `certificates`:

```
expires_at        DateTime?   ตั้งตอนกดเผยแพร่ครั้งแรก = published_at + 24 เดือน
files_deleted_at  DateTime?   ตั้งตอนลบไฟล์สำเร็จ
```

**ต้องเก็บเป็นวันที่จริง ไม่ใช่คำนวณสดจาก `published_at`** เพราะถ้าวันหนึ่งเปลี่ยนนโยบายเป็น 3 ปี
ของเก่าต้องไม่ถูกยืดอายุตามไปโดยไม่ตั้งใจ และแอดมินต้องเห็นได้ว่าใบไหนจะหายวันไหน

ตั้งค่าครั้งเดียวตอนเผยแพร่ครั้งแรกเท่านั้น (`expires_at ??= ...`) เผยแพร่ซ้ำหลังแก้ไขไม่รีเซ็ตนาฬิกา

### ตัวกวาด

งานชนิดใหม่ `EXPIRE` ใน worker ทำงานวันละครั้ง (เช็คเวลาที่รันล่าสุดจากตารางสถานะ
ไม่ต้องเพิ่ม service ให้เสียเงิน):

1. หาใบที่ `expires_at <= วันนี้` และ `files_deleted_at IS NULL`
2. ลบไฟล์บน R2 ทีละ 1000 คีย์ต่อคำสั่ง (ถูกและเร็วที่สุด) ไฟล์ที่หายไปแล้วข้ามไป
3. ตั้ง `files_deleted_at` แล้วล้าง `pdf_key` / `preview_key` ทั้งใน `certificates` และ `staging_pages`
4. บันทึกสรุปลง log

ทำเป็นก้อนย่อยและบันทึกทีละก้อน พังกลางทางแล้วรันซ้ำได้ ไม่ต้องเริ่มใหม่หมด

### หน้าแอดมิน

- รายการ "ใกล้หมดอายุใน 30 วัน" เห็นล่วงหน้าเสมอ
- ปุ่ม **ต่ออายุรอบนี้อีก 1 ปี** เผื่อมีโรงเรียนขอ
- ปุ่ม **ลองดูว่าจะลบอะไรบ้าง** (dry-run) แสดงรายการโดยไม่ลบจริง
- สวิตช์ `RETENTION_ENABLED` **ปิดเป็นค่าตั้งต้น** เปิดเมื่อพร้อม

### ฝั่งผู้ใช้

ของที่หมดอายุแล้วจะค้นไม่เจอ ไม่ต้องขึ้นข้อความอธิบายเพิ่มในหน้า "ไม่พบ"

แต่ต้องแจ้งนโยบายไว้ตั้งแต่วันแรก โดยเพิ่มข้อความ **ท้ายการ์ดของแต่ละคน ครั้งเดียว**
ไม่ใช่ใต้ชื่อรายการสอบทุกอัน เพราะคนที่มีหลายรายการสอบจะเห็นข้อความเดิมซ้ำ 2-3 รอบในหน้าเดียว

```

│ SOMMOT THODSOBRABOB                      │
│ ระดับชั้นล่าสุด PRIMARY 4                  │
│ TIMO (3) · HKIMO (1)                     │
├──────────────────────────────────────────┤
│ TIMO  Thailand International Math…       │
│   ปี 2026 · รอบชิงชนะเลิศ                 │
│   [การ์ดเกียรติบัตร]                       │
│ HKIMO  Hong Kong International Math…     │
```

ตัวหนังสือเล็ก สีเทา ไม่ต้องเด่น เป็นการแจ้งให้ทราบ ไม่ใช่คำเตือน

### ผลต่อพื้นที่เก็บ

หลังทำครบทั้ง 3 งาน (5 รายการสอบ × 2 รอบ = 10 รอบ/ปี):

| อะไร | ต่อรอบ | คงค้างในระบบ |
|---|---|---|
| เกียรติบัตร PDF | 196 MB | 2 ปี = 3.9 GB |
| รูปตัวอย่าง (หลังลดขนาด) | 15 MB | 2 ปี = 0.3 GB |
| ZIP ต้นฉบับ | 360 MB | **ชั่วคราวเท่านั้น** |
| **รวมคงที่** | | **~4.2 GB** |

อยู่ในโควตาฟรีของ R2 (10 GB) แบบไม่โตขึ้นเรื่อย ๆ อีกต่อไป
ถ้าไม่ทำอะไรเลย ปีที่ 2 จะแตะ 12 GB และเริ่มเสียเงิน

## ลำดับการลงมือ

| ขั้น | งาน | ตรวจว่าเสร็จด้วย |
|---|---|---|
| 1 | ลดขนาดรูป + สคริปต์ re-render | วัดขนาดไฟล์จริงหลังนำเข้าได้ ~85 KB/ใบ |
| 2 | ลบ ZIP เมื่อจับคู่ครบ (เงื่อนไข 4 ข้อ + หน้าแอดมิน) | pytest เคสครบ/ไม่ครบ แล้วทดลองกับรอบจริงในเครื่อง |
| 3 | `expires_at` + แสดงวันหมดอายุในหน้าแอดมิน **ยังไม่ลบอะไร** | เผยแพร่รอบทดสอบแล้วเห็นวันหมดอายุถูกต้อง |
| 4 | ตัวกวาด + dry-run + สวิตช์ปิด | pytest ด้วยนาฬิกาปลอม + dry-run กับข้อมูลจริง |
| 5 | เปิดใช้จริง + ปุ่มต่ออายุ + ข้อความแจ้งนโยบาย + เอกสาร | ทดลองให้ใบทดสอบหมดอายุ แล้วไฟล์หายจาก R2 และค้นไม่เจอ |

## กฎที่ต้องเขียนกันไว้ในโค้ด

1. **ห้ามลบของที่ยังไม่เคยเผยแพร่** — ใบที่ถูกกันไว้ (เช่นรอไฟล์เหรียญทอง) ไม่มี `expires_at` จึงไม่โดนกวาด
2. **ห้ามลบ ZIP ถ้ายังมีคนตกหล่น** — เงื่อนไข 4 ข้อต้องครบทุกข้อ ขาดข้อเดียวคือไม่ลบ
3. **สวิตช์ปิดเป็นค่าตั้งต้น** ทั้งตัวกวาดอายุและตัวลบ ZIP เปิดเมื่อทดสอบแล้วเท่านั้น
4. **ลบแล้วต้องบันทึกว่าลบเมื่อไหร่** ไม่ใช่ปล่อยให้ไฟล์หายไปเฉย ๆ จนไม่มีใครรู้ว่าเกิดอะไรขึ้น
5. **นโยบาย 2 ปีต้องประกาศตั้งแต่วันแรกที่เปิดใช้** ไม่ใช่ตอนใกล้ครบกำหนด
   ถ้าประกาศว่าเก็บ 2 ปีแล้วไม่ลบจริง จะแย่กว่าไม่ประกาศเลย
