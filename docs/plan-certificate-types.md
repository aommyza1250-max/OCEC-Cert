## 1. ทำไมต้องมี phase นี้

ระบบเวอร์ชันแรกถูกออกแบบและจูนกับแบบฟอร์มเดียว คือ **HKIMO รอบชิงชนะเลิศ (Final)** โดยมีสมมติฐานว่า:
1. ไฟล์ต้นทางเป็น PDF รวมเล่มที่แยกตามโฟลเดอร์รางวัลเสมอ
2. จุดยึดชื่อใช้คำว่า `This is awarded to` เสมอ
3. บรรทัด `from` คือสัญชาติ และต้องกรองเฉพาะ `from THAILAND`
4. รอบคัดเลือกและรอบชิงชนะเลิศมีโครงสร้างคล้ายกัน

**เมื่อนำไฟล์จริงของทั้ง 5 รายการสอบมารวมกัน พบว่าสมมติฐานเหล่านี้ผิดเกือบทั้งหมด:**
- OCEC มี **5 รายการสอบ × 2 รอบ = 10 รูปแบบ**
- บางรายการมีไฟล์เป็น **รูปภาพ `.jpg` รายบุคคล** (BBB Final, HKISO, HKICO Final รวมกว่า 1,094 ไฟล์) — *ตรวจสอบแล้วพบว่าเกิดจากการที่แอดมินนำไฟล์ PDF ต้นฉบับไปแปลง/แก้ไขเอง ส่วนไฟล์จากต้นทางฮ่องกงจริงจะเป็น PDF รวมเล่มทั้งหมด* (สำหรับ HKISO แบบ PDF ต้นฉบับกำลังอยู่ระหว่างนำมาเพิ่ม)
- บางรายการ **ไม่มีจุดยึด `This is awarded to`** (BBB)
- บางรายการ **ซอยโฟลเดอร์ซ้อนตามระดับชั้น** (`Gold/P3/*.jpg` ใน HKISO Heat)
- บางรายการ **โฟลเดอร์มีคำนำหน้า** (`HKICO Gold` ใน HKICO Final)
- รอบ Heat ทั้งหมด **บรรทัด `from` คือชื่อโรงเรียน** ไม่ใช่สัญชาติ

ถ้าไม่ปรับสถาปัตยกรรมตอนนี้ การนำเข้ารอบอื่นๆ จะพังเงียบๆ หรือล้มเหลวทันทีที่อัปโหลดไฟล์

## 3. ปัญหาเชิงโครงสร้างเดิม

ค่าคอนฟิกใน `apps/worker/app/config.py` ถูกฮาร์ดโค้ดเป็นค่าเดียวของทั้งระบบ:
```python
nationality_pattern   = "from\s+THAILAND"
country_line_prefix   = "from "
name_anchor           = "This is awarded to"
level_line_prefix     = "for outstanding achievement in"
cert_no_pattern       = "(?:Cert\s+)?No:\s*(\d+)"
award_line_pattern    = "^(.+?)\s+Award$"
round_year_pattern    = "(Final|Heat)\s+Round\s+(\d{4})"
```

และความเข้าใจผิดใน `split.py` และ `zip_bundle.py`:
- กรองสัญชาติเฉพาะเมื่อ `round == "FINAL"`
- รับเฉพาะไฟล์ที่ลงท้ายด้วย `.pdf` เท่านั้น (ข้าม `.jpg` ทั้งหมด)
- อ่านรางวัลจากโฟลเดอร์ชั้นเดียว `path.parent.name`

**ผลกระทบ:**
1. นำเข้าไฟล์ JPG (BBB Final, HKISO, HKICO Final) ไม่ได้เลยเพราะระบบหา PDF ไม่เจอ
2. HKISO Heat พังทันทีเพราะได้ชื่อรางวัลเป็น `P3`, `S2`
3. HKICO Final พังทันทีเพราะ `normalize_award("HKICO Gold")` ไม่รู้จักคำว่า `HKICO`
4. BBB อ่านชื่อเด็กไม่เจอเพราะไม่มี `This is awarded to`

## 4. ข้อเสนอเชิงสถาปัตยกรรม: แยกไฟล์ Handler รายรายการสอบ (Strategy Pattern)

แทนที่จะเขียน `if-else` ขนาดยักษ์ใน `split.py` หรือยัด regex ทุกอย่างรวมกัน **ให้แยกไฟล์จัดการเฉพาะของแต่ละรายการสอบ** 

### โครงสร้างไฟล์ใน `apps/worker/app/handlers/`

```text
apps/worker/app/handlers/
├── __init__.py          <-- get_handler(program_code, round)
├── base.py              <-- BaseHandler (รวมตรรกะร่วม: clean text, normalize, Fallback)
├── hkimo.py             <-- class HKIMOHeatHandler, HKIMOFinalHandler
├── timo.py              <-- class TIMOHeatHandler, TIMOFinalHandler
├── bbb.py               <-- class BBBHeatHandler, BBBFinalHandler (แกะชื่อไฟล์ JPG ได้ตรงๆ)
├── hkiso.py             <-- class HKISOHeatHandler, HKISOFinalHandler (แกะโฟลเดอร์เกรด 2 ชั้น)
└── hkico.py             <-- class HKICOHeatHandler, HKICOFinalHandler (ตัดแต่งวิชา Scratch/Python)
```

### หน้าที่และ Interface กลาง (`BaseHandler`)

```python
class BaseHandler(ABC):
    """กติกากลางที่ทุกรายการสอบสืบทอดไปใช้"""

    @abstractmethod
    def discover_items(self, zip_source: Path) -> list[BundleItem]:
        """ค้นหาไฟล์ใน ZIP — รองรับทั้ง PDF และ JPG พร้อมแกะชื่อรางวัลจากโฟลเดอร์"""

    @abstractmethod
    def extract_page_info(self, item: BundleItem, page_data: Any) -> PageInfo:
        """สกัดข้อมูล (ชื่อ, โรงเรียน, เลขสอบ, ระดับชั้น, รางวัล)"""

    def should_filter_foreigner(self, page_text: str) -> bool:
        """ตรวจว่าเป็นผู้เข้าสอบคนไทยหรือไม่ (Default: รอบ Heat ไม่กรอง, Final กรอง THAILAND)"""
```

### การวิเคราะห์ข้อดี - ข้อเสีย (Pros & Cons)

| ด้าน | ข้อดี | จุดที่ต้องระวัง / วิธีแก้ |
|---|---|---|
| **ความปลอดภัย (Blast Radius)** | **เป็นศูนย์** — แก้โค้ดของ BBB ไม่มีทางทำให้ HKIMO หรือ TIMO พัง | - |
| **รองรับ Edge Case** | ทำได้ไม่จำกัด เช่น BBB Final แกะ `cert_no` จากชื่อไฟล์ได้ตรงๆ ไม่ต้องรัน OCR | ต้องคอยคุม Interface ให้สอดคล้องกัน |
| **ความซ้ำซ้อน (Duplication)** | - | มีความเสี่ยง Copy-Paste ซ้ำๆ -> **แก้โดยใส่ตรรกะกลางไว้ที่ `BaseHandler`** แล้วไฟล์ย่อยเขียนเฉพาะส่วนที่ Override |
| **ความอ่านง่ายของโค้ด** | ไม่มี Spaghetti `if-else` ในตัวประมวลผลหลัก | ไฟล์ในระบบเพิ่มขึ้น (5 ไฟล์หลัก) แต่ยังถือว่าน้อยมากสำหรับ 5 รายการสอบ |
| **การทดสอบ (Testing)** | เขียน Automated Test รายรายการได้แบบ 1:1 กับไฟล์จริง | ต้องเขียนเทสครอบคลุมทุก Handler |
| **การเพิ่มรายการใหม่** | มีความชัดเจนใน Git diff | ต้อง Deploy เมื่อมีรายการใหม่ (แต่ OCEC แทบไม่เพิ่มรายการสอบใหม่) |

## 5. แผนงานย่อย เรียงตามลำดับความสำคัญ

### 5.1 สถาปัตยกรรม Handler กลาง (`BaseHandler` & Dispatcher)
- สร้างโฟลเดอร์ `apps/worker/app/handlers/`
- ทำ `BaseHandler` ที่มีตรรกะมาตรฐานเท่ากับระบบปัจจุบัน
- เชื่อม `run_split` ให้เรียกใช้ `get_handler(program_code, round)`
- **เกณฑ์ผ่าน:** รันกับไฟล์ HKIMO Final เดิมแล้วผลลัพธ์ต้องเท่าเดิม 100% (243/243 หน้า)

### 5.2 กลไกรองรับไฟล์รูปภาพ (.jpg, .png) แปลงเป็น PDF อัตโนมัติ (Admin Fallback)
- แม้ไฟล์ต้นทางจากผู้จัดสอบจะเป็น PDF รวมเล่มทั้งหมด แต่แอดมินอาจมีเคสแก้ไขเกียรติบัตรรายบุคคลแล้วเซฟเป็นรูปภาพ
- ปรับปรุงตัวอ่าน ZIP ให้ตรวจจับทั้งไฟล์ `.pdf` และรูปภาพ `.jpg`, `.jpeg`, `.png`
- หากพบไฟล์รูปภาพ ให้ระบบแปลงเป็น PDF 1 หน้า (`pymupdf`) อัตโนมัติก่อนเข้ากระบวนการ Staging เพื่อรักษามาตรฐานระบบให้เป็น PDF-First เสมอ
- **เกณฑ์ผ่าน:** สามารถนำเข้าชุดไฟล์ BBB Final หรือเกียรติบัตรที่แก้เป็นรูปภาพเดี่ยวได้โดยระบบแปลงและประมวลผลได้ราบรื่น

### 5.3 รองรับโครงสร้างโฟลเดอร์ซ้อนหลายชั้น (Smart Folder Traversal)
- ปรับการหาชื่อรางวัลจาก `path.parent.name` เป็นการเดินค้นหาโฟลเดอร์ชั้นบนขึ้นไปจนกว่าจะพบชื่อรางวัลที่ระบบรู้จัก
- รองรับโครงสร้าง `Gold/P3/file.jpg` ของ `HKISO Heat` ให้ระบุรางวัลเป็น `GOLD` ได้ถูกต้อง
- **เกณฑ์ผ่าน:** อ่านไฟล์ HKISO Heat 674 ไฟล์แล้วระบุรางวัลได้ถูกต้องครบทุกใบ

### 5.4 กำจัด Prefix ชื่อรายการสอบออกจากชื่อโฟลเดอร์
- เพิ่มชื่อย่อการแข่งขัน (`HKICO`, `HKIMO`, `TIMO`, `BBB`, `HKISO`) เข้า `AWARD_NOISE`
- ทำให้โฟลเดอร์ `HKICO Gold`, `HKICO Silver` แปลงเป็น `GOLD`, `SILVER` ได้อย่างถูกต้อง
- **ต้องแก้ทั้ง 2 ภาษา:** `apps/worker/app/normalize.py` และ `apps/web/src/lib/normalize.ts`
- **เกณฑ์ผ่าน:** อ่านโฟลเดอร์ HKICO Final ทั้ง 109 ไฟล์ได้โดยไม่เกิด `ZipLayoutError`

### 5.5 Handler เฉพาะของ BBB (ไม่มี Anchor + ดึงข้อมูลจากชื่อไฟล์)
- **BBB Heat:** สร้างตรรกะจุดยึดชื่อใหม่ (ชื่ออยู่บรรทัดถัดจาก `1st/2nd/3rd Prize Award`)
- **BBB Final:** สร้างฟังก์ชันแกะ `cert_no`, `name`, `award` จากชื่อไฟล์ `BBB F_{year}_{cert_no}_{name}_{award}.jpg` โดยตรง
- **เกณฑ์ผ่าน:** สกัดข้อมูล BBB Heat ได้ครบ 1,166 หน้า และ BBB Final ครบ 199 หน้า

### 5.6 ดึงชื่อโรงเรียนจากรอบ Heat เก็บลงฐานข้อมูล
- บรรทัด `from` ในรอบ Heat ทั้งหมด ให้ถือเป็น "ชื่อโรงเรียน"
- บันทึกลง `staging_pages` และส่งต่อไปยัง `students.school` (ผ่าน `normalizeSchool`)
- ป้องกันการนำเข้าผิด: หากรอบ Heat ตรวจพบว่าข้ามหน้าเกิน 50% ให้สั่งหยุดงานทันที
- **เกณฑ์ผ่าน:** นำเข้า HKIMO Heat แล้วเห็นชื่อโรงเรียนปรากฏบนการ์ดผลลัพธ์การค้นหา

### 5.7 จัดการระดับชั้นที่มีชื่อวิชา และช่วงปีการศึกษา
- ใน `HKICO`: ตัดแต่งระดับชั้นที่มีชื่อวิชา (เช่น `PRIMARY 2 in SCRATCH` -> ชั้น `PRIMARY 2`, วิชา `SCRATCH`)
- ปรับ Regex ตรวจจับปีให้รองรับช่วงปีการศึกษา `2025 - 2026`
- **เกณฑ์ผ่าน:** จับคู่กับ Excel ได้แม้ใน Excel จะมีเฉพาะชื่อระดับชั้น

### 5.8 รองรับรางวัลเข้าร่วม (`PARTICIPATION`) ในระบบ
- เพิ่มสีป้าย (Badge Tone) และไอคอนเฉพาะสำหรับ `PARTICIPATION` ใน `AwardBadge.tsx`
- เพิ่มคำแปลภาษาไทย `"เข้าร่วม"` ใน `AWARD_LABELS` และลำดับใน `AWARD_ORDER`
- เพิ่มตัวเลือกในหน้าแอดมิน: "เผยแพร่รางวัลเข้าร่วมหรือไม่"
- **เกณฑ์ผ่าน:** หน้าเว็บแสดงป้าย "เข้าร่วม" สีสวยงาม และแอดมินสามารถเลือกซ่อน/แสดงได้

### 5.9 เครื่องมือตรวจสอบก่อนนำเข้าจริง (Pre-upload Inspector)
- พัฒนา `check_real_files.py` ให้เรียก Handler ตามรายการสอบและรอบ
- ใช้ตรวจสอบความเข้ากันได้ของไฟล์ ZIP ก่อนที่แอดมินจะกดยืนยันการนำเข้า

## 7. เรื่องที่ต้องยืนยันกับทีมจัดสอบก่อนเริ่ม

1. **ไฟล์ต้นฉบับ PDF ของ HKISO และ TIMO Final:** รอรับไฟล์ PDF รวมเล่มของ HKISO (เพื่อนำมาตรวจทานว่าโครงสร้างตรงกับมาตรฐาน PDF ของรายการอื่นหรือไม่) และติดตามสถานะไฟล์ของ TIMO Final
2. **นโยบายการเผยแพร่รางวัลเข้าร่วม:** ต้องการให้เด็กที่ได้เฉพาะใบเข้าร่วมสามารถค้นหาบนหน้าเว็บได้ทุกคนหรือไม่ (รอบ Heat มีใบเข้าร่วมเกือบ 900 ใบ)
3. **การนำเข้าของ BBB:** ยืนยันว่า BBB เป็นรหัสรายการสอบแยกต่างหากในระบบ (`BBB`) ใช่หรือไม่
4. **วิชาของ HKICO:** ต้องการให้แสดงวิชา (Scratch, Python, C++) บนหน้าผลการค้นหาด้วยหรือไม่ หรือแสดงเฉพาะระดับชั้น

## 8. กฎเหล็กที่ต้องรักษา (Non-negotiable Rules)

1. **แก้ Normalize ต้องแก้ทั้ง Python และ TypeScript เสมอ** พร้อมอัปเดตเคสใน `shared/normalize-cases.json`
2. **ชื่อโฟลเดอร์ยังเป็นแหล่งความจริงหลักของรางวัล** ข้อความบนหน้าใช้เพื่อ Cross-check เท่านั้น (เพราะรอบ Heat ทั้งหมดและใบ Perfect Score ไม่พิมพ์รางวัลบนหน้า)
3. **ไม่มั่นใจ ส่งให้แอดมินตัดสิน (ห้ามเดา)** — การที่เกียรติบัตรไปโผล่ผิดคนร้ายแรงกว่าการที่ระบบบอกว่าต้องตรวจทาน
4. **ไม่แตะ Branch `main` จนกว่าจะผ่านการทดสอบกับไฟล์จริงครบทั้ง 5 รายการสอบ**
